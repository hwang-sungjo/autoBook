# ONDECK · 나의 예매 플래너

야구 예매 일정과 알림, 좌석 후보를 준비하는 웹 앱입니다. Vercel에 배포하거나 로컬에서 실행할 수 있으며 사용자 설정은 각 브라우저에 저장됩니다.

## Vercel 배포

- GitHub 저장소를 Vercel에서 Import합니다. 프레임워크는 `Other`, 루트 디렉터리는 저장소 루트를 사용합니다.
- `vercel.json`이 정적 페이지 디렉터리 `dist`, Node.js 시간 조회 함수 `api/site-clock.js`, 서울 리전 `icn1`을 설정합니다. 별도 설치·빌드 명령이나 환경변수는 필요하지 않습니다.
- 새 브라우저의 기본 선행 보정은 사용자 요청대로 **62ms**입니다. 이미 저장된 사용자 설정은 유지합니다. 로컬 주소와 배포 주소의 저장 공간은 별개이므로 기존 일정·후보는 JSON 내보내기/가져오기로 옮길 수 있습니다.
- Vercel에서는 사용자의 컴퓨터에서 로컬 서버를 실행할 필요가 없습니다. 자동 열기는 브라우저에서 수행하므로 대기 탭과 컴퓨터는 계속 켜 두어야 합니다.
- 시간 측정 경로는 **Vercel 서버 → 공개 사이트 루트**입니다. 사용자 브라우저의 예매·대기열 접수 지연으로 해석하지 않습니다.
- 측정 캐시는 같은 실행 인스턴스 안에서 1분간 공유됩니다. 서로 다른 Vercel 인스턴스의 캐시는 독립적입니다. 시각 패킷을 잘못 재사용하지 않도록 API의 브라우저·CDN 캐시는 비활성화합니다.
- `.vercelignore`는 배포에 필요한 정적 파일과 API 소스만 업로드합니다. 브라우저 저장 설정, 실행 스크린샷, 로그, 문서, 로컬 인증 파일은 배포에 포함하지 않습니다.

## 실행

Node.js 20 이상에서 프로젝트 폴더를 열고 실행하세요.

```sh
npm run dev
```

브라우저에서 **http://127.0.0.1:4173** 을 엽니다. 종료할 때 터미널에서 `Ctrl+C`를 누릅니다. 다른 포트가 필요하면 `PORT=4174 npm run dev`로 실행할 수 있습니다.

## 사용

1. **일정 등록**에서 공식 페이지의 이벤트 이름, 오픈 시각, 관람 인원과 예매 주소를 입력합니다. 모든 입력 시각과 화면 표시 시각은 **Asia/Seoul(KST)** 입니다.
2. **알림 설정**에서 5분·1분·10초 전 알림과 소리, 브라우저 알림을 설정합니다. 일정 카드의 **알림 켜기**를 눌러 시작합니다. 오픈 시각에도 알립니다.
3. 로그인, 본인 인증, 팝업, 결제 수단을 직접 확인한 뒤 체크리스트를 표시합니다.
4. **내 후보로 시작하기** 또는 **후보 추가**에서 직접 확인한 좌석 정보를 기록합니다. 첫 화면의 가상 예시는 실제 경기장이나 잔여 좌석 정보가 아닙니다.
5. 선호 조건의 화살표를 눌러 순서를 바꾸면 비교 결과가 갱신됩니다. 목록 또는 개념도의 번호를 누르면 비교 중인 후보를 표시합니다.
6. **예매 페이지 열기**로 공식 페이지를 열고 예매 과정을 직접 진행합니다.
7. 지정 시각에 페이지를 열려면 **사이트 시간 보정됨 · 추정** 상태와 **가정 기반 지연 보정** 설정을 확인하고 자동 열기 버튼을 누릅니다. 기본 프로필은 **오픈 62ms 전에 자동 열기**입니다. 미리 열린 **예매 페이지 대기** 탭을 앞에 두고 유지하면 보정된 목표 시각에 해당 탭이 공식 주소로 한 번 이동합니다. 앱 또는 대기 탭의 **자동 열기 취소**로 중지할 수 있습니다.

## 사이트 시간과 자동 열기

앱 서버가 등록된 예매 주소의 호스트(`tickets.interpark.com` 또는 `ticket.interpark.com`) 루트에 HEAD 요청을 보내 응답의 `Date`와 `Age`를 읽습니다. 예매 주소의 경로나 로그인 정보는 이 시간 확인 요청에 전달하지 않습니다. 같은 호스트의 요청은 같은 실행 인스턴스에서 합쳐 처리하고 1분간 재사용합니다. 외부 리다이렉트는 따라가지 않습니다.

응답의 초 단위 시간, 캐시 경과 시간, 측정 왕복 지연을 반영해 시각을 추정합니다. 이후에는 단조 시계(`performance.now`)로 진행하며 기기 시계를 바꿔도 기존 추정 시각이 갑자기 바뀌지 않습니다. HTTP Date는 [RFC 9110](https://www.rfc-editor.org/rfc/rfc9110.html#section-6.6.1)에 정의된 **응답 생성 시각의 근사값**입니다. CDN의 응답 시각이 실제 예매 처리 서버의 시계와 같다고 보장할 수 없으며, 초 단위 정보로 밀리초 정확도를 보장할 수 없습니다.

최근 3분 안의 서로 다른 표본을 보관하고, 네트워크 지연·시간 양자화·표본 경과에 따른 계산상 불확실성이 가장 작은 표본을 선택합니다. 캐시된 같은 측정값을 다시 읽어도 표본 수를 늘리지 않습니다. 패널에는 앱 서버의 왕복 지연, 기기 시계와의 차이, 계산상 불확실성, 표본 수, 왕복 지연 변동폭을 표시합니다. 이 불확실성은 추정 모델의 값이며 실제 예매 서버의 시계 오차를 포함한 보장 범위가 아닙니다.

연결 구간 측정은 **앱 서버 → 사이트 루트의 HTTP/1.1 HEAD**입니다. DNS, TCP, TLS, 요청 전송 후 응답 헤더까지 걸린 시간을 분리하고, 기존 소켓 재사용을 표시합니다. Chrome의 실제 예매 주소 접속·대기열 접수·화면 도착 시간으로 해석하면 안 됩니다. 이 앱은 다른 출처인 공식 페이지의 도착 시간을 자동으로 읽지 않습니다.

대기 탭은 보정된 자동 열기 시각의 30초 전에 해당 호스트의 `dns-prefetch`·`preconnect` 힌트를 한 번 요청합니다. 공식 페이지 내용을 미리 요청하지 않으며, 브라우저가 힌트를 사용하거나 연결을 재사용한다는 보장은 없습니다. [MDN의 preconnect 설명](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Attributes/rel/preconnect)에 따른 연결 준비 기능입니다. `Age`는 캐시 나이이며 빼 줄 접속 지연이 아닙니다.

### 사용자가 요청한 가정 프로필

- 동시 접속: **최소 120,000명**. 지연 계산에 사용하는 배수가 아닌 시나리오 기록입니다.
- 가정 왕복 지연: **116ms**, 실행 지연 여유: **4ms**. 사용자 요청으로 유지한 시험값이며 Chrome의 실제 예매 요청 지연이나 다수 사용자의 최적값으로 검증한 값이 아닙니다.
- 계산: **왕복 지연 가정 / 2 + 실행 지연 여유**를 오픈 시각에서 뺍니다. 반올림한 정수 ms를 사용하며 합계는 최대 1,000ms입니다. 배포 기본값은 **116 / 2 + 4 = 62ms**입니다.
- 15:00:00.000 오픈 예시의 이동 목표는 **14:59:59.938**입니다. 실제 이동 시각·페이지 도착·대기열 접수 시각의 정밀도는 보장하지 않습니다.
- **가정 기반 지연 보정**에서 접속 인원, 왕복 지연, 실행 지연 여유를 수정하고 **보정값 저장**을 누릅니다. 선행 보정을 끄면 0ms로 동작합니다. 왕복 지연은 0~2,000ms, 실행 지연 여유는 0~100ms, 합계 선행 보정은 최대 1,000ms로 제한합니다. 기존 설정의 실행 지연 여유는 0ms입니다.
- 접속 인원만 바꿔도 지연을 자동으로 늘리지 않습니다. 측정된 RTT가 변해도 저장한 가정 프로필은 자동으로 바뀌지 않습니다.
- 설정은 브라우저에 저장되고 JSON 내보내기에 포함됩니다. 보정 항목이 없는 기존 설정은 요청한 120,000명·116ms·실행 여유 4ms·선행 62ms 프로필로 초기화합니다. 기존 보정 프로필이 있으면 해당 값을 유지합니다.
- 예약할 때 가정과 보정값을 예약 기록에 복사합니다. 설정을 바꾸면 활성 자동 열기를 취소하므로 새 값으로 다시 예약해야 합니다. 이전 실행 기록은 보정하지 않습니다.

이 프로필은 사용자가 지정한 부하·지연 가정입니다. 실제 접속자가 12만 명이라는 사실만으로 같은 지연이나 빠른 진입을 보장할 수 없습니다. 초 단위의 시계 불확실성은 62ms보다 크며, 실제 오픈 전에 도착할 가능성이 있습니다.

자동 열기 실행 시에는 선택한 표본의 불확실성과 왕복 지연, 연결 준비 요청 여부, 보정된 예정 시각 대비 이동 명령의 지연을 저장합니다. 공식 오픈 시각 대비 차이는 별도로 기록하며 음수이면 공식 오픈 시각보다 앞선 이동 명령입니다. 직전 실행 지연은 실제 대기열 접수 지연이 아닙니다. 2026년 10월 16일의 단일 연결 측정값과 해석은 [CALIBRATION.md](CALIBRATION.md)에 기록했습니다.

실행 후에는 화면에 **직전 실행 당시 기록**을 표시합니다. 이 값은 현재 조회한 홈페이지 측정값과 구분됩니다. 2026년 11월 2일 사용자 보고는 대기번호 약 9,000번이며, 저장된 실행 명령 지연은 약 4ms였습니다. 다음 비교용 설정은 기존 왕복 가정 116ms에 실행 여유 4ms를 더한 **62ms 선행**입니다. 한 번의 결과로 보정의 효과나 5,000번대에 필요한 시간을 검증하지는 못했습니다. 실행 지연이 다음에도 4ms라는 가정이 포함됩니다.

- 최근 3분 이내의 사이트 시간 정보가 있어야 자동 열기를 예약하고 실행할 수 있습니다. 확인 전에는 기기 시계를 표시하고, 기존 정보가 오래되면 이전 추정값임을 표시합니다.
- 브라우저 팝업 제한을 고려해 예약 버튼을 누르는 순간 로컬 대기 탭을 엽니다. [MDN의 팝업 동작 설명](https://developer.mozilla.org/en-US/docs/Web/API/Window/open)에 따라 타이머가 새 팝업을 만드는 방식은 사용하지 않습니다.
- 대기 탭은 같은 일정을 여러 탭에서 열어도 Web Locks로 실행 상태를 먼저 기록한 한 탭만 이동합니다. 자동 열기에 필요한 기능이 없는 브라우저에서는 예약 버튼이 비활성화됩니다.
- **대기 탭을 닫거나 새로고침하면 예약이 취소됩니다.** 대시보드만 새로고침하는 것은 열린 대기 탭의 예약을 취소하지 않습니다.
- 일정의 이름·오픈 시각·주소를 수정하거나 삭제하고, 설정을 가져오면 기존 자동 열기를 취소합니다. 자동 열기 예약은 JSON 백업에 포함하지 않습니다.
- 네트워크, 브라우저 타이머 제한, 절전·잠자기 및 공식 페이지의 로딩 시간 때문에 실제 이동과 페이지 도착이 늦어질 수 있습니다. 대기 탭을 앞에 두고 컴퓨터를 켜 두세요. 로컬 실행 중이면 로컬 서버도 유지해야 합니다. 오픈 시각을 10초 넘게 지난 뒤 재개하면 자동으로 이동하지 않습니다.

## 좌석 비교 방식

위에서부터 5·4·3·2·1의 비중을 부여합니다. 내야·1루 쪽·통로 쪽·응원석은 해당 여부를, 필드와의 가까움은 사용자가 입력한 0~100 값을 반영하여 100점 만점으로 계산합니다. 순위는 입력한 후보 사이의 선호도이며 예매 성공 가능성이 아닙니다.

시야 방해석, 장애인석, 관람 인원보다 좌석 수가 적은 후보는 항상 순위에서 제외됩니다. 통로 위치, 좌석 연석 여부와 잔여 수량은 공식 좌석도에서 직접 확인해야 합니다. 개념도의 위치는 조건에 따른 참고용 배치이며 실제 좌석도가 아닙니다.

## 알림과 저장

- 알림은 **이 페이지가 열려 있을 때만** 작동합니다. 사이트 응답 시각 보정값이 있으면 같은 추정 시각을 사용하며, 보정값이 없으면 기기 시계를 사용합니다.
- 브라우저 절전, 백그라운드 타이머 제한, 기기 잠자기 또는 OS 알림 설정에 따라 알림이 늦거나 표시되지 않을 수 있습니다. 잠자기에서 돌아왔을 때 5분 이상 지난 알림은 보내지 않습니다.
- 소리 알림은 페이지에서 버튼을 누르는 등 한 번의 상호작용이 필요합니다. 브라우저 알림은 사용자가 허용해야 합니다.
- 일정의 시각·이름·주소를 변경하거나 설정을 가져오면 알림은 꺼집니다. 내용을 확인한 뒤 다시 켜세요.
- 일정·후보·체크리스트·설정은 해당 브라우저의 `localStorage`에 저장됩니다. 서버에는 사용자 데이터를 기록하지 않습니다.
- **내보내기**로 JSON 백업을 저장하고 **사용 안내 → 설정 가져오기**로 복원할 수 있습니다. 가져오기는 현재 설정을 대체합니다.
- 비밀번호, 인증 정보, 결제 정보는 입력하거나 저장하지 않습니다.

이 앱은 NOL 티켓과 별개인 개인용 보조 도구입니다. 자동 열기는 저장한 공식 페이지로 한 번 이동합니다. 공식 사이트의 버튼 조작, 대기열 진입, 실시간 좌석 조회·선점, 결제 화면 이동 및 결제는 사용자가 직접 진행합니다.

## 파일

- `dist/index.html`, `styles.css`, `app.mjs`: 화면과 사용자 흐름
- `dist/core.mjs`: KST 날짜, 일정 검증, 알림, 저장 데이터 정규화
- `dist/seat-model.mjs`: 좌석 제외 조건과 선호도 점수
- `dist/timing.mjs`: 사이트 시계 보정, 자동 열기 상태와 한 번만 실행하는 처리
- `dist/standby.html`, `standby.mjs`: 지정 시각에 공식 페이지로 이동하는 대기 탭
- `server.mjs`, `server-clock.mjs`, `connection-probe.mjs`: 정적 파일, 사이트 시간, 연결 구간 측정을 제공하는 로컬 서버

- `tests/`: 날짜·URL·알림·가져오기·좌석 점수·사이트 시각·자동 열기 및 HTTP 서버 테스트
